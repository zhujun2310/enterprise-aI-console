# Performance

性能目标与优化记录（以“演示级体验 + 可持续演进”为原则）。

## 总目标

- 首屏可用：优先渲染布局壳与关键 Widget，避免大面积白屏
- 可持续扩展：模块拆分清晰，避免单文件/单 chunk 无限膨胀
- 实时可控：实时推送频率可控，避免前后端资源被拖垮
- 可回归：每次优化都能通过 `build / lint` 等基础验证手段回归

## 当前现状（基于仓库实现）

- Admin 采用 Vite 构建，生产构建可能出现 “chunk > 500kB” 告警（属于体积告警，不影响功能）
- Dashboard 已使用 SSE 实时推送，频率为 5s 级别，属于“演示安全区”
- 图表已封装在模块内的 `EChart` 组件，暂未抽离到 `packages/charts`

## 指标建议（可选）

- 首屏：Dashboard 首次渲染 < 2s（本地开发机）
- 实时：SSE 连接稳定，断线自动重连（前端具备恢复策略）
- 构建：单入口主 chunk 体积控制（告警阈值可调，但建议先拆包）

## 已落地策略

### 1) Dashboard：快照 + SSE

- 首次进入：走快照接口保证“立即可见”
- 后续更新：SSE 增量推送保证“实时感”
- 页面聚焦/可见：触发一次被动刷新，避免长时间后台导致数据滞后

### 2) Widget 容器统一三态

- Widget 层统一 `loading / empty / error` 三态，不让页面出现不可控的空洞与抖动

## 优化清单（从低成本到高收益）

### A. 拆包（推荐优先）

- 把图表库按需加载：在 Widget 需要时动态 import 图表相关模块
- 路由级懒加载：对非核心页面进行 lazy

### B. 数据层

- Dashboard 快照增加缓存窗口（例如 3~10 秒内复用）
- 避免重复请求：进入页面/切换可见性时做节流

### C. 渲染层

- 对大列表（设备列表/告警列表）引入虚拟列表（后续项）

## 如何验证

- 本地：`pnpm --filter @enterprise-ai-console/admin build`
- 全局：`pnpm lint`
- 行为验证：打开 `/dashboard`，观察 SSE 状态与 Widget 刷新是否符合预期
