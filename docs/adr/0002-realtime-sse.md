# ADR 0002: Dashboard 实时方案选择（SSE）

## Status

Accepted

## Context

Dashboard 需要实现“打开页面后数据可自动变化”的体验，数据流以服务端单向推送为主，包括：

- KPI 更新
- 设备状态统计更新
- 告警新增/状态变化
- 趋势点追加

同时要求：

- 开发与部署成本低
- 易于穿透常见代理/负载均衡
- 前端实现可控，断线可恢复

## Decision

采用 SSE（Server-Sent Events）作为 Dashboard 的实时通道，并配套“快照 + SSE”策略：

- 首次进入：通过 `/dashboard/snapshot` 获取完整快照，保证首屏可用
- 后续更新：通过 `/sse/dashboard` 推送增量事件，保证实时感
- 前端连接管理：统一封装在 `useSse`，支持断线重连与可见性恢复刷新

## Alternatives

### 1) WebSocket

优点：

- 双向通信，扩展空间大

缺点：

- 基础设施与代理层要求更高
- 对当前“单向推送”的需求来说偏重

### 2) 轮询（Polling）

优点：

- 实现简单

缺点：

- 资源浪费明显
- 实时体验差，刷新粒度难以兼顾性能与实时性

## Consequences

正面：

- 满足当前单向推送需求
- 实现/部署成本低
- 和快照配合能保证“可用 + 实时”

代价：

- 只适合单向推送，后续若需要双向交互再引入 WebSocket
- 需要明确事件协议（type/payload），避免变成不可维护的自由格式
